## スキャン

通常ファイルのみを対象とします。名前が `.` で始まるファイル・ディレクトリとその配下、symlink、FIFO などの特殊ファイルは除外します。明示的な include パターンでも、この除外は変更できません。パターンの構文とルールごとの対象範囲は [Location と glob パターン](../configuration/README.ja.md#location-と-glob-パターン) を参照してください。

ルールに `include` パターンを指定すると、一致するファイルが存在し得ないディレクトリは探索しません。たとえば `/Volumes` に対する `Untitled*/PRIVATE/M4ROOT/CLIP/*` は、`Untitled*` に一致するボリューム内の指定階層だけを探索します。`**` を含むパターンでは、そのワイルドカード以降を再帰的に探索します。

存在しない入力元は、一致するファイルがないものとして扱います。既存の入力元の一部が読めない場合、`scan` は読めたレコードを出力したうえでエラー終了します。`preview`・`apply` は不完全なスキャンを受け付けません。

`preview`・`apply` は `when` で必要とするメタデータを抽出します。アクションで使う日時・カメラ情報なども、同じルールの `when` で参照が必要です。`scan`・`explain` は診断用にメタデータ全体を抽出します。抽出項目の選択とルールの照合は [Rules と評価順](../configuration/README.ja.md#rules-と評価順) を参照してください。

## 実行

`preview` は入力元をスキャンし、ファイルの変更や shell の実行なしに計画全体を検証します。`apply` は再度スキャンして全操作を検証し、確認を挟まず実行します。実行内容には、その時点のファイルの状態が反映されます。プレビューは保存済みの計画ではありません。

実行前に入力の同一性・サイズ・更新日時をスキャン時の状態と照合し、変更を検出した場合は停止します。`--force` を指定しても、既存の宛先は上書きしません。実行中に新たな競合を検出した場合も停止し、検証済みの計画から宛先名を選び直すことはありません。

最後の `move`・`trash` は、前のルールも含め、その入力に対するコピーがすべて成功した場合だけ実行します。既存宛先との競合でコピーが1つでも skip された場合、残りのコピーは続けますが、最後の move・trash は省略して元ファイルを残します。既存ファイルとの内容比較は行いません。`preview` では既存のコピー先による省略を警告し、表示する move・trash はコピー成功を条件とする操作として扱います。`apply` は省略理由を stderr に表示し、JSON 出力では結果の `skipped` 配列にも記録します。

エラー時は実行を停止し、完了済みのコピーや shell による変更は巻き戻しません。shell アクションはコピー前の元ファイルを直接変更でき、後続コピーが skip された場合も加工済みの元ファイルを残します。実行条件と設定例は [Shell](../configuration/README.ja.md#shell) を参照してください。

コピーは権限・mtime・拡張属性（macOS）を保持し、一時ファイルを同期してから既存の宛先を上書きせずに配置します。別ボリュームへの移動は、コピーしたファイルと宛先ディレクトリを同期してから元ファイルを削除します。macOS では拡張属性を保持できない場合にコピーを停止し、属性を失ったまま移動を完了することを防ぎます。

`copy` は macOS で自動的に clone を試し、非対応や別ボリュームの場合は通常コピーに切り替えます。Linux は通常コピーです。それ以外の clone エラーでは停止します。容量検証では、clone で節約できる場合も通常コピーに必要な容量を見積もります。`clone`・`hardlink`・`symlink` アクションは非対応です。独立したファイルを作るには `copy` を使ってください。

操作の順序と競合時の方針は [競合時の方針と action の順序](../configuration/README.ja.md#競合時の方針と-action-の順序) を参照してください。OS 標準のゴミ箱に必要な環境、実行時に確認する項目、明示的な退避先を使う `--trash-dir` は [Trash](../configuration/README.ja.md#trash) に記載しています。

## メタデータ

対応形式と日時の取得元は次のとおりです。

- JPEG、TIFF、PNG、WebP、HEIC/HEIF、AVIF、DNG、CR2、NEF、PEF、ARW
- CR3、CRW、RW2
- QuickTime creation date、`©day`、embedded XML、`mvhd` を含む MOV、MP4
- PNG の `eXIf`、`tEXt`、`iTXt` creation date
- XMP、THM、同名 JPEG サイドカー
- 最終的な代替値としてファイルシステムの作成日時・更新日時

### 日時の精度

秒未満の精度は保証しません。CR3/CRW/RW2 以外の画像では、EXIF の `SubSecTimeOriginal`・`SubSecTimeDigitized` を撮影日時に合成せず、通常の EXIF 日時は秒単位で扱います。小数部を復元するための再解析は行いません。XMP や CR3/CRW/RW2 のデコーダーなどが直接返す日時に小数秒が含まれる場合は、その値が残ることがあります。

`raw` はデコーダーが返した値であり、小数秒の元の桁列を保持する保証はありません。連写の順序やファイル名の一意性を小数秒に依存させず、名前の衝突には `on_conflict` を使ってください。

撮影日時が得られなければ、最終的にファイルシステムの作成日時・mtime を使います。取得元はルールの `captured_source` で区別できます。ただし、要求したメタデータの抽出に失敗した入力は、代替の日時が得られても処理対象から除外します。日時の変数は [条件式](../configuration/README.ja.md#条件式)、タイムゾーンの解釈は [Settings](../configuration/README.ja.md#settings) を参照してください。

### 抽出の制限

動画抽出では `mdat` を読みません。メタデータ抽出は上限付きのワーカープールで並列化し、式と正規表現は設定読み込み時に一度だけコンパイルします。

XMP サイドカーは 8 MiB、PNG テキストチャンクは 1 MiB を上限とします。デコーダーの Read・Seek でキャンセルを確認するため、タイムアウトは協調的な中断です。

Tamis は純 Go のメタデータパーサーを使う単一バイナリで、ExifTool のインストールは不要です。外部コマンドは明示的な shell アクションでのみ実行します。macOS と Linux を `CGO_ENABLED=0` でビルドできます。OS 標準のゴミ箱の実行環境は [Trash](../configuration/README.ja.md#trash) を参照してください。
